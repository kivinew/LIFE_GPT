ЛОГИКА
--------------------------------------------------

После смерти клетки:

1. Клетка переходит в состояние Dead.

2. Запускается процесс разложения.

3. После начала разложения создаётся объект OrganicPool.

4. Лужа существует независимо от клетки.

5. После завершения разложения клетка удаляется.

--------------------------------------------------
ПОВЕДЕНИЕ ЛУЖИ
--------------------------------------------------

Лужа должна содержать:

- координаты
- радиус
- массу
- запас питательных веществ
- возраст
- скорость распада
- коэффициент испарения
- коэффициент поглощения
- цвет (или параметры визуализации)

Каждый игровой тик необходимо:

- увеличивать возраст;
- уменьшать количество питательных веществ;
- уменьшать радиус;
- удалять лужу после полного распада.

--------------------------------------------------
ПОГЛОЩЕНИЕ
--------------------------------------------------

Если клетка находится внутри радиуса лужи,

она может получать питание.

Количество питания ограничивается:

- скоростью поглощения клетки;
- остатком вещества в луже.

После поглощения:

уменьшается запас лужи.

--------------------------------------------------
ПРОИЗВОДИТЕЛЬНОСТЬ
--------------------------------------------------

Игра должна поддерживать тысячи клеток
и сотни одновременно существующих луж.

Поэтому:

не использовать дорогие вычисления в Python.

Все циклы, проходящие по большим коллекциям объектов,
по возможности перенести в Cython.

Использовать:

- cdef class
- cdef функции
- typed memoryviews
- cdef int
- cdef float
- libc.math
- отключение boundscheck
- отключение wraparound
- inline-функции при необходимости

Избегать:

Python-объектов внутри внутренних циклов.

--------------------------------------------------
РАЗДЕЛЕНИЕ PYTHON/CYTHON
--------------------------------------------------

Python:

- создание объектов;
- удаление объектов;
- сериализация;
- игровые события;
- взаимодействие с ECS (если есть);
- загрузка ресурсов.

Cython:

- обновление состояния луж;
- вычисление радиусов;
- вычисление расстояний;
- поиск клеток внутри радиуса;
- массовое обновление объектов;
- диффузия (если потребуется);
- любые тяжёлые математические операции.

--------------------------------------------------
АРХИТЕКТУРА
--------------------------------------------------

Не использовать глобальные переменные.

Не создавать сильных зависимостей между классами.

Каждый класс должен иметь одну ответственность.

Использовать существующие менеджеры объектов.

Если имеется ObjectPool —
использовать его.

Если имеется SpatialHash, QuadTree или Grid —
использовать их для поиска ближайших клеток.

Не выполнять поиск по всем клеткам каждый кадр.

--------------------------------------------------
ПАМЯТЬ
--------------------------------------------------

Минимизировать выделение памяти.

Не создавать временные списки внутри Update().

По возможности переиспользовать объекты.

Использовать object pooling.

--------------------------------------------------
КОД
--------------------------------------------------

Код должен соответствовать принципам:

- SOLID
- DRY
- KISS

Все публичные методы должны иметь краткое описание.

Все магические числа вынести в конфигурацию.
