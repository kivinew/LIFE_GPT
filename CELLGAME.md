# Промт для ИИ-агента: разработка игры «Симулятор эволюции клетки»

Скопируй этот промт целиком в Claude Code (или другого агента) как техзадание для старта проекта.

---

## Роль и задача

Ты — ведущий геймдев-инженер. Нужно спроектировать и поэтапно реализовать 2D-игру-симулятор эволюции клетки с редактируемым геномом, вдохновлённую Thrive, The Bibites и Evolving-Protozoa. Работай итеративно: сначала минимальный играбельный прототип (MVP), затем наращивай сложность слоями. После каждого этапа — рабочая, тестируемая версия.

## Концепция игры

Игрок управляет одноклеточным организмом в водной среде. Между поколениями (после успешного размножения) открывается **редактор генома**, где тратятся очки мутаций на изменение анатомии, поведения и метаболизма клетки. Остальная популяция вида и конкурирующие виды эволюционируют автоматически (авто-эволюция) на основе тех же правил отбора. Долгосрочная цель — усложнение (от прокариота к эукариоту, затем к многоклеточности), но прогресс не обязателен — можно процветать и на простом уровне.

## Технологический стек

- **Язык/движок**: TypeScript + Canvas2D (или PixiJS) для быстрого старта в браузере — не требует установки, легко итерировать и показывать прогресс. Альтернатива для более серьёзного проекта — Godot 4 + C#, если игрок ориентируется на десктоп-сборку (как Thrive).
- Рекомендация по умолчанию: **TypeScript + PixiJS + Vite**, если не указано иное.
- Физика: простой кастомный 2D-движок (круговые коллайдеры для клеток) — не нужен полноценный физдвижок на старте.
- Хранение состояния: JSON-сериализация генома и мира для сохранений.

## Архитектура генома (ядро системы)

Геном — список генов фиксированной структуры, каждый ген влияет на один или несколько параметров:

1. **Структурные гены** (по аналогии с органеллами Thrive):
   - тип мембраны (мягкая/подвижная — быстрее, но уязвимее; жёсткая/клеточная стенка — медленнее, но защищённее)
   - органеллы: митохондрия (аэробное дыхание), хлоропласт (фотосинтез), хемопласт, вакуоль (запас ресурсов), жгутик (скорость), пили/токсины (атака), рецепторы (детекция среды)
   - размер клетки, форма (влияет на манёвренность и скорость метаболизма)

2. **Поведенческие гены** (по аналогии с The Bibites):
   - минимальная эволюционируемая нейросеть (входы: уровень ресурсов, наличие еды/угроз рядом, свет, температура; выходы: направление движения, потребление, деление, выброс токсина)
   - структура сети должна мутировать (добавление/удаление связей и нейронов — NEAT-подобный подход), а не только веса

3. **Метаболические компромиссы** (trade-offs, как в WKBae/Life-Simulator):
   - каждый параметр должен быть в обратной зависимости хотя бы от одного другого (скорость ↔ энергозатраты, размер ↔ манёвренность, атака ↔ защита) — это не даёт эволюции сходиться к «читерскому» одному оптимуму

## Механика отбора и размножения

- Клетка тратит энергию (АТФ) на движение, метаболизм, поддержание органелл; получает энергию из фотосинтеза/поедания ресурсов/других клеток
- Размножение доступно при накоплении достаточного запаса энергии/ресурсов
- При размножении: crossover (если есть половое размножение) + случайные мутации генов с настраиваемой частотой
- Между «сессиями» игрока фоновая популяция вида и NPC-виды считаются агрегированной моделью (population dynamics, как auto-evo в Thrive), а не симулируются покадрово — это резко снижает вычислительную нагрузку
- Видообразование: особи с генетической дистанцией выше порога считаются отдельным видом (как в Life-Simulator)

## Редактор генома (UI)

- Открывается после успешного размножения
- Показывает бюджет «очков мутации» на сессию редактирования
- Визуальный редактор клетки: клик по гексагональной/круглой сетке для размещения органелл (как в Thrive)
- Отдельная вкладка — граф нейросети поведения с возможностью вручную поменять связи (как в Bibitinator/BiBrainer), но по умолчанию она эволюционирует автоматически
- Показ статистики: конкурентоспособность вида, популяция, причины вымирания/успеха прошлого поколения

## Этапы реализации (двигайся по порядку, не забегай вперёд)

### Этап 0 — Прототип ядра симуляции
- Одна клетка, управляемая вручную (WASD/мышь), плавает по 2D-миру, ест частицы ресурса, теряет энергию со временем, умирает при истощении
- Простейший рендер: круг + мембрана

### Этап 1 — Геном и деление
- Ввести структуру генома (JSON), 3-4 базовых гена (размер, скорость, тип питания, мембрана)
- Реализовать деление клетки при накоплении энергии, копирование генома с мутацией

### Этап 2 — Редактор
- UI-экран между «раундами», трата очков мутации на изменение генов
- Сохранение/загрузка генома вида

### Этап 3 — Популяция и отбор
- Фоновая симуляция N особей вида + 1-2 конкурирующих вида с собственными геномами
- Простая модель приспособленности (fitness) на основе энергобаланса, влияющая на численность популяции между поколениями

### Этап 4 — Поведенческие нейросети
- Минимальная эволюционируемая сеть принятия решений вместо жёстко закодированного AI для NPC-клеток
- Мутация структуры сети (добавление нейронов/связей)

### Этап 5 — Усложнение и биомы
- Разные зоны с разными условиями (свет, температура, ресурсы) — миграция как эволюционная стратегия
- Задел под переход к эукариоту/многоклеточности (не обязательно реализовывать полностью в MVP)

## Ограничения и принципы

- На каждом этапе — работающая и играбельная сборка, не переходи к следующему, пока текущий не стабилен
- Баланс важнее реализма: если параметр не создаёт компромисс, эволюция его "сломает" (найдёт вырожденную стратегию) — тестируй через ускоренный прогон N поколений и смотри, не сходится ли геном к абсурдному решению
- Код геномной системы держи расширяемым: добавление нового гена не должно требовать правки движка симуляции
- Начни с ответа: предложи структуру проекта (папки/модули) и схему данных генома (TypeScript interface/JSON schema), прежде чем писать игровой код
