# c_python_rules

## Назначение

Этот skill задаёт правила для:
- запуска Python-кода;
- сборки и запуска C/C++-кода;
- выбора правильной консоли для проверки программ.

Используй этот skill, когда задача связана с:
- запуском `.py` файлов;
- установкой/подхватом Python-зависимостей;
- сборкой `.c` / `.cpp`;
- проверкой программ с большим выводом в консоль;
- запуском кода в Windows-окружении проекта.

## Основные правила

1. Для выполнения Python-кода используй **uv**, а не прямой вызов `python`.
2. Базовый способ запуска Python:
   - `uv run script.py`
   - `uv run python script.py`
   - если нужно выполнить модуль: `uv run -m module_name`.
3. Если Python-скрипт запускается в контексте проекта, предпочитай `uv run`, чтобы использовалось проектное окружение и зависимости.
4. Не предлагай `pip install` и ручное создание venv, если задача может быть решена командой `uv add` и `uv venv`.

5. Для сборки C/C++ в проекте используй **Cygwin GCC**.
6. Базовые команды:
   - C: `gcc file.c -o file.exe`
   - C++: `g++ file.cpp -o file.exe`
7. Считай Cygwin-компилятор основным компилятором проекта.
8. Не подменяй его на MSVC или MinGW без явного запроса пользователя.
9. Используй обычные gcc/g++-флаги в стиле Unix, так как Cygwin работает с GCC именно в такой модели.

10. Если программа даёт слишком большой вывод в консоль, **не запускай её во встроенной консоли vscode**.
11. В таких случаях:
   - запускай через обычную `cmd`;
   - или через `pwsh`;
   - или перенаправляй вывод в файл.
12. Если есть риск переполнить консоль, сначала предложи безопасную проверку:
   - ограничить вывод;
   - запустить на малом наборе данных;
   - сохранить результат в файл.

## Когда использовать

Используй этот skill, если пользователь просит:
- запустить Python-скрипт;
- собрать C/C++ программу;
- проверить код из проекта в Windows;
- разобраться, чем запускать `.py`, `.c`, `.cpp`;
- адаптировать команды под локальную консоль;
- избежать проблем с большим stdout/stderr.

## Как действовать

### Python
1. Определи, является ли задача запуском файла, модуля или проекта.
2. Для запуска используй `uv run`.
3. Если у скрипта есть аргументы, передавай их после имени файла.
4. Если вывод слишком большой, не используй antigravity-консоль.

Примеры:
```bash
uv run script.py
uv run python script.py
uv run -m app.main
uv run script.py --input data.txt
```

### C / C++
1. Определи, это C или C++.
2. Собери через Cygwin GCC/G++.
3. Если программа создаёт большой вывод, запускай её в `cmd` или `pwsh`.
4. При необходимости предлагай вывод в файл.

Примеры:
```bash
gcc main.c -o main.exe
g++ main.cpp -o main.exe
main.exe > output.txt
```

## Правила ответа

Когда отвечаешь по этой теме:
- сначала давай готовую команду;
- затем кратко поясняй;
- если есть риск большого вывода, отдельно предупреждай;
- если команда зависит от shell, явно указывай: `cmd`, `pwsh` или `Cygwin`.

## Ограничения

- Не предлагай запуск Python через `python script.py`, если нет причины обходить `uv`.
- Не предлагай другой C-компилятор, если пользователь явно не просил.
- Не запускай шумные программы во встроенной antigravity-консоли.
- Не давай абстрактные инструкции вида "запусти как обычно" — указывай точную команду.

```bash
uv run -m module_name
```

### Сборка C

```bash
gcc main.c -o main.exe
```

### Сборка C++
```bash
g++ main.cpp -o main.exe
```

```bash
main.exe > output.txt
```
